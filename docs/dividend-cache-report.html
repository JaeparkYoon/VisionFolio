Core Logic

3단계 캐싱 전략

DividendRepositoryImpl.getDividends() 호출 시 아래 순서로 동작합니다.

1

캐시 조회

cachedAt 타임스탬프가 오늘 날짜인지 확인합니다. 오늘이면 DB 캐시를 즉시 반환하고 API를 호출하지 않습니다.

CACHE HIT → 즉시 반환
2

API 호출 + 캐시 갱신

캐시가 없거나 어제 이전 데이터면 API를 호출합니다. 성공 시 기존 캐시를 삭제하고 새 데이터를 저장한 뒤 반환합니다.

CACHE MISS → API → 저장 → 반환
3

Stale 캐시 폴백

API 호출이 실패하면(네트워크 오류, 402 등) 날짜에 관계없이 기존 캐시를 반환합니다. 오래된 데이터라도 빈 화면보다 낫습니다.

API FAIL → 오래된 캐시라도 반환
// DividendRepositoryImpl.kt — getDividends() 핵심 로직 // 1. 캐시 조회 val cachedAt = cacheDao.getCachedAt(holding.id) if (cachedAt != null && isSameDay(cachedAt, System.currentTimeMillis())) { val cached = cacheDao.getByHoldingId(holding.id) return cached.map { it.toDomain() } // cache hit! } // 2. API 호출 val records = runCatching { fetchFromApi(holding) }.getOrNull() if (records != null) { cacheDao.deleteByHoldingId(holding.id) cacheDao.insertAll(records.map { it.toEntity(holding.id, now) }) return records } // 3. API 실패 → stale 캐시 폴백 val stale = cacheDao.getByHoldingId(holding.id) return if (stale.isNotEmpty()) stale.map { it.toDomain() } else emptyList()

Schema

캐시 테이블 구조

Room DB dividend_cache 테이블. 하나의 holdingId에 여러 행(배당 이력)이 저장됩니다.

컬럼 타입 설명
idINTEGER PK자동 증가 기본 키
holdingIdTEXT보유 종목 ID (캐시 키)
stockNameTEXT종목명
stockCodeTEXT종목 코드
dividendPerShareREAL주당 배당금
paymentDateTEXT배당 지급일
currencyTEXT"KRW" 또는 "USD"
cachedAtINTEGER캐시 저장 시각 (millis)
Scope

캐싱 범위

per-share 데이터만 캐싱하고, 수량 기반 계산은 실시간으로 수행합니다.

항목 캐싱 비고
주당 배당금 YES API에서 받은 원본 데이터
종목명 / 코드 / 지급일 / 통화 YES 배당 기록 메타데이터
보유 수량 (quantity) NO ObserveDividendData에서 실시간 계산
배당 총액 (annualTotal) NO quantity × dividendPerShare 매번 계산
배당 수익률 (yield) NO currentPrice 기반 매번 계산

💡 설계 포인트

보유 수량이 변경되어도 캐시를 무효화할 필요가 없습니다. holdingRepo.observe() Flow가 수량 변경을 감지하면 combine에 의해 buildSummary()가 재실행되고, 이때 getDividends()는 캐시 히트하여 per-share 데이터만 빠르게 반환합니다.

Resilience

에러 내성 설계

API 실패 상황에서의 동작 비교입니다.

✓ API 성공

  • 결과 반환
  • 캐시 저장 (갱신)

⚠ API 실패 + 캐시 있음

  • 기존: 빈 화면 표시
  • 변경: stale 캐시 반환

✗ API 실패 + 캐시 없음

  • emptyList() 반환
  • (기존과 동일)

🛠 핵심 변경: runCatching 전파 구조

기존에는 fetchFmpDividends() / fetchKrDividends() 내부에 각각 runCatching이 있어 예외를 emptyList()로 삼켰습니다. 이를 제거하여 예외가 상위 getDividends()의 runCatching까지 전파되도록 수정했습니다. 이를 통해 stale 캐시 폴백이 정상 동작합니다.
